# CloudHub 企业知识库 AI 问答助手 · 售前解决方案

> 场景：面向中型企业（零售 / 制造 / 政企）的**内部知识 + 产品资料智能问答**落地方案
> 定位：数据 + AI 售前演示方案　|　作者：王俊翰　|　类型：售前 PoC 配套文档

---

## 一、需求分析（客户痛点）

企业在"知识"上有三个反复出现的痛点：

1. **资料散落、找不到。** 产品手册、售后政策、价格方案、客户案例、内部制度分散在网盘、邮件、各部门手里，一线销售和客服查一个口径要问三个人。
2. **重复问答、成本高。** 客服 60% 以上的问题高度重复（"支持什么系统""怎么收费""退款政策"），全靠人工检索文档、逐条手打回答。
3. **通用大模型不敢直接用。** 直接问 ChatGPT 会**编造**（幻觉），且无法引用、无法审计、涉密数据不能出域——企业需要的是"只根据自家文档回答、每句话都能点回原文"的可信助手。

**一句话需求：** 用一个只吃"企业自己的知识库"、回答可溯源不编造、支持私有化部署的智能问答助手，把找资料和重复答疑的成本降下来。

## 二、解决方案设计

### 2.1 整体架构（RAG 检索增强生成）

```
用户提问
  → ① 文档接入层：解析 PDF/Word/网页/扫描件（loader）
  → ② 分块层：语义切分成片段，保留出处（splitter）
  → ③ 向量化 + 关键词索引：Embedding 入库（vectorstore）
  → ④ 检索层：向量召回 + 关键词混合检索，取 Top-K（retriever）
  → ⑤ 重排层：Rerank 精排，挑最相关片段
  → ⑥ 生成层：大模型基于命中片段生成答案，强制引用标注
  → 输出：带 [1][2] 引用的答案 + 可溯源原文 + 置信度/边界提示
```

对应本原型的可见演示：右侧「RAG 检索链路」面板实时展示每一层的产物，「引用来源」面板展示命中的原文片段与相关度评分。

### 2.2 关键能力与选型

| 能力 | 方案 | 为什么客户在意 |
|---|---|---|
| 可溯源 | 每句回答挂原文引用，点击跳转 | 企业"不胡说、可审计"的底线 |
| 防幻觉 | 知识库未命中时主动拒答（见"写诗"演示） | 避免拿编造内容对外答复 |
| 私有化 | 支持本地 / 信创环境部署，数据不出域 | 政企、金融合规刚需 |
| 混合检索 | 向量 + 关键词召回 | 专有名词、型号、政策条款召回更准 |
| 免安装 | B/S 架构浏览器直接用 | 一线销售、客服零门槛上手 |

### 2.3 与传统 BI / 传统客服的差别

传统 BI 解决"看数据"，本方案解决"问知识"；传统关键词搜索给一堆链接，本方案给**一句带出处的答案**。两者叠加 = 企业既看得懂数、又问得出答案。

## 三、价值测算（ROI）

以一家 100 人、含 20 人客服/销售团队的企业为例（保守估算）：

- **答疑提效：** 重复咨询占比约 60%，助手自动应答后，人均检索/打字时间每次省约 4 分钟，按日均 30 次/人计 → 每人日省约 2 小时，客服/销售团队年化节省 ≈ **¥60 万+**（按人力成本估算）。
- **上手周期：** 新人熟悉产品/政策口径，从"数周带教"缩短到"随问随答"，培训成本下降约 **40%**。
- **口径一致：** 所有对外回答统一来自同一知识库，减少因"各说各话"造成的合规与客诉风险。
- **投入：** 标准版/专业版按席位订阅，10 席起、年付 8 折，支持 30 天免费 POC —— **先用真实问题跑，见效再采购**。

> 演示话术："这套助手不是替代您的团队，是把团队里最重复、最耗人的那 60% 问答先接走，让一线把时间花在真正需要判断的事上。"

## 四、实施路径（怎么落地）

| 阶段 | 周期 | 交付 |
|---|---|---|
| P0 POC 验证 | 1–2 周 | 用客户真实文档搭最小知识库，验证召回与问答效果 |
| P1 知识治理 | 2–3 周 | 文档接入、分块策略、口径梳理、权限分级 |
| P2 上线集成 | 2 周 | 对接 IM / 官网 / 工单系统，私有化或 SaaS 部署 |
| P3 运营优化 | 持续 | 命中率监控、坏例回流、知识库定期更新 |

**风险控制：** 先小范围高重复场景验证价值，再横向扩展；涉密数据走私有化，满足不出域要求。
